### 1. DIAMOND Homology Integration
DIAMOND is a fast alternative to BLAST for protein sequence alignment, ideal for homology-based function transfer. This adds a "sequence similarity" baseline or hybrid layer to your pLM predictions, often improving performance on proteins with close homologs in the training set.

#### Steps:
- **Install DIAMOND**: Download the binary from the official GitHub (buchfink/diamond) and add it to your PATH. No pip install needed, but ensure it's executable.
- **Prepare Database**: Use training sequences to build a DIAMOND database (once, cache it).
- **Run Alignments**: For test proteins, align against the train DB and parse hits.
- **Transfer Annotations**: For each test protein, aggregate GO terms from top hits (weighted by alignment score).
- **Hybrid Prediction**: Blend homology scores with your model's logits (e.g., via weighted average).
- **Integration**: Add a `homology/` module, update `trainer.py` or add a `predictor.py` for ensemble, and include in `submission.py`. Use configs for parameters like e-value threshold or top-k hits.

```python
import subprocess
import pandas as pd
import numpy as np
from Bio import SeqIO  # Assuming biopython is installed
from data_ingest.label_builder import LabelBuilder  # Reuse your label builder

class DiamondHomology:
    def __init__(self, config, label_builder: LabelBuilder):
        self.config = config
        self.label_builder = label_builder
        # Assume labels are dict of ontology -> protein_id -> multi-hot vector

    def build_db(self, train_fasta: str):
        """Build DIAMOND DB from train_sequences.fasta (run once)."""
        cmd = [
            self.config.diamond_path, "makedb",
            "--in", train_fasta,
            "-d", self.config.db_path
        ]
        subprocess.run(cmd, check=True)

    def run_alignment(self, test_fasta: str, output_m8: str):
        """Align test sequences against train DB."""
        cmd = [
            self.config.diamond_path, "blastp",
            "-q", test_fasta,
            "--db", self.config.db_path,
            "-o", output_m8,
            "--max-target-seqs", str(self.config.max_hits),
            "--evalue", str(self.config.evalue),
            "--outfmt", "6 qseqid sseqid pident length mismatch gapopen qstart qend sstart send evalue bitscore"
        ]
        subprocess.run(cmd, check=True)

    def predict(self, test_ids: np.ndarray, output_m8: str, ontology: str):
        """Transfer labels via homology for one ontology (MFO/BPO/CCO). Returns scores array."""
        hits = pd.read_csv(output_m8, sep="\t", header=None,
                           names=["qid", "sid", "pident", "length", "mismatch", "gapopen",
                                  "qstart", "qend", "sstart", "send", "evalue", "bitscore"])
        
        scores = np.zeros((len(test_ids), len(self.label_builder.go_terms[ontology])))  # Shape: num_test x num_terms
        id_to_idx = {pid: i for i, pid in enumerate(test_ids)}
        labels = self.label_builder.labels[ontology]  # Assume dict protein_id -> multi-hot
        
        for qid in test_ids:
            q_hits = hits[hits["qid"] == qid].sort_values("bitscore", ascending=False).head(self.config.max_hits)
            if q_hits.empty:
                continue
            weights = q_hits["bitscore"] / q_hits["bitscore"].sum()  # Normalize weights
            for _, hit in q_hits.iterrows():
                sid = hit["sid"]
                if sid in labels:
                    scores[id_to_idx[qid]] += weights[_] * labels[sid]  # Weighted sum of labels
        
        return scores  # Use sigmoid if needed for probabilities
```

### 2. Zero-shot GO Term Encoding
This enables predictions for rare or new GO terms without training data by encoding terms' textual descriptions and comparing to protein embeddings.

#### Steps:
- Use a model like ESM-2 (already in your system) or a specialized one like OntoGPT for GO term embeddings.
- Embed GO term descriptions (from go-basic.obo) and protein sequences.
- Compute similarity (e.g., cosine) as prediction scores.
- Integrate as a fallback for low-confidence model predictions or ensemble.

#### Code Snippet (new `models/zero_shot.py`):
```python
import torch
from transformers import AutoTokenizer, AutoModel  # Add huggingface transformers to requirements
from obonet import read_obo  # Already in requirements

class ZeroShotPredictor:
    def __init__(self, model_name="facebook/esm2_t6_8M_UR50D"):
        self.tokenizer = AutoTokenizer.from_pretrained(model_name)
        self.model = AutoModel.from_pretrained(model_name)
        self.go_terms = {}  # term_id -> embedding

    def embed_go_terms(self, obo_path: str):
        graph = read_obo(obo_path)
        for term_id, data in graph.nodes(data=True):
            desc = data.get('def', data.get('name', ''))  # Use definition or name
            inputs = self.tokenizer(desc, return_tensors="pt", padding=True, truncation=True)
            with torch.no_grad():
                emb = self.model(**inputs).last_hidden_state.mean(dim=1)  # Mean pool
            self.go_terms[term_id] = emb.squeeze()

    def predict(self, protein_embs: torch.Tensor, ontology_terms: list):
        """protein_embs: num_proteins x emb_dim from your pLM."""
        term_embs = torch.stack([self.go_terms[term] for term in ontology_terms])
        sim = torch.nn.functional.cosine_similarity(protein_embs.unsqueeze(1), term_embs.unsqueeze(0), dim=2)
        return sim  # Shape: num_proteins x num_terms
```

### 4. Hierarchical Loss Regularization
Enforce GO hierarchy in training by penalizing predictions that violate parent-child relations.

#### Steps:
- Add a term to BCE loss: for each predicted child term, ensure parent score >= child score.
- Use your ancestor_indices from GO loader.

#### Code Snippet (update `trainer.py`):
```python
def hierarchical_loss(logits, ancestors):
    penalty = 0
    for child_idx, parent_idxs in enumerate(ancestors):
        if parent_idxs:
            penalty += torch.relu(logits[:, child_idx] - logits[:, parent_idxs].min(dim=1)[0]).mean()
    return penalty

# In training loop
loss = bce_loss + config.lambda_hier * hierarchical_loss(logits, go_loader.ancestor_indices[onto])
```
